# Financial AI Assistant

A production-grade RAG (Retrieval-Augmented Generation) system for querying financial regulatory documents and GL accounting data using natural language.

Built entirely with local, open-source models — no paid APIs required.

![Python](https://img.shields.io/badge/Python-3.10+-blue)
![Mistral](https://img.shields.io/badge/LLM-Mistral%207B-orange)
![Qdrant](https://img.shields.io/badge/VectorDB-Qdrant-red)

---

## What it does

**Document Q&A** — Ask questions about financial regulatory documents (Basel III, BaFin circulars) and get precise answers with page citations.

**GL Data Q&A** — Ask natural language questions about General Ledger data and get SQL-backed answers with visualisations.

**Automatic routing** — The system detects whether your question is about documents or data and routes it to the right pipeline automatically.

## Evaluation Results (RAGAs)

Evaluated on 4 Basel III regulatory questions using Mistral 7B locally.

| Metric            | Score     |
|-------------------|-----------|
| Faithfulness      | 0.950     |
| Answer Relevancy  | 0.864     |
| Context Precision | 1.000     |
| Context Recall    | 1.000     |
| **Overall**       | **0.953** |

### Note on embedding fine-tuning

Synthetic fine-tuning was attempted using 60 question-chunk pairs
generated by Mistral. With this dataset size, marginal score changes
were observed. The base model already achieves strong performance on
financial regulatory text (0.953 overall RAGAs score).

Finding: 500+ domain-specific pairs would be needed for meaningful
improvement. With only one source document (127 chunks), generating
sufficient training data would require adding more financial documents
such as FINREP templates, BaFin circulars, and IFRS standards.

## Setup

**Prerequisites:** Python 3.10+, Docker, Ollama

```bash
# 1. Clone the repo
git clone https://github.com/YOUR_USERNAME/financial-rag.git
cd financial-rag

# 2. Create virtual environment
python -m venv venv
source venv/bin/activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Start Qdrant
docker run -p 6333:6333 \
  -v $(pwd)/qdrant_storage:/qdrant/storage \
  qdrant/qdrant

# 5. Start Ollama and pull Mistral
ollama serve
ollama pull mistral

# 6. Add documents
# Place PDFs into the documents/ folder

# 7. Ingest documents
python ingest.py

# 8. Generate GL database
python data/generate_gl_data.py

# 9. Run the app
python -m streamlit run app.py
```

## Key Design Decisions

**Why local models?**
Financial data is sensitive. Running Mistral and embeddings locally
means no data ever leaves the machine — important for regulated
environments like banking.

**Why hybrid search?**
Pure vector search misses exact financial terms like "CET1", "FINREP",
"HGB §253". Combining BM25 keyword search with vector search gives
the best of both approaches. In evaluation, BM25 contributed higher
scores than vector search for exact regulatory term queries.

**Why SQLite instead of Snowflake?**
For portfolio demonstration purposes, SQLite provides identical query
semantics to production warehouses without requiring credentials or
network access. The Text-to-SQL pipeline is warehouse-agnostic and
can be pointed at any SQL database by changing the connection string.

**Why synthetic GL data?**
Real GL data from financial institutions is proprietary and
confidential. The synthetic dataset mirrors real HGB/IFRS chart of
accounts structure used in German banking, making it realistic for
demonstration while avoiding any data privacy concerns.
